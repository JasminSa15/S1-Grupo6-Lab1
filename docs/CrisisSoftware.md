# Comparación entre el desarrollo tradicional y el desarrollo ágil 

Hoy día existen muchas formas de optimizar, organizar y administrar un proyecto de software, debido a que los proyectos requieren planificación, organización y colaboración, hacen del trabajo una tarea más fácil y limpia de llevarlo a cabo. Es por ello, que con el tiempo surgieron diferentes enfoques para gestionar los proyectos, por ejemplo el "Desarrollo tradicional" y el "Desarrollo ágil", estos enfoques nos permiten llevar un trabajo más limpio, pero antes necesitamos saber qué son y cómo funcionan. 

## ¿Qué es el desarrollo tradicional?
En este enfoque el proyecto se organiza mediante etapas, estas etapas deben ser previamente definidas y planificadas, la idea con este desarrollo es que antes de que se empiece a desarrollar se logre determinar puntos importantes para la creación por ejemplo: 
* Qué necesita el cliente. 
* Qué funciones tendrá el software.
* Cómo se va a construir. 
* Cuánto tiempo puede tomar. 
* Cuánto puede costar.
Un ejemplo de esto podría ser el famoso "Waterfall" o "Cascada" y es que se llama así debido a que las estapas van avanzando de forma secuencial, es como que si una etapa lleva a la siguiente y sucesivamente.

## ¿Cómo funciona? 
Este desarrollo podríamos pensarlo como un sistema para una biblioteca, por ejemplo llevar el plan en etapas, así:
1- Requisitos
2- Diseño
3- Desarrollo
4- Pruebas
5- Entrega
6- Mantenimiento

**-Requisitos:** Acá determinamos qué es lo que nuestro cliente quiere, por ejemplo, si quiere generar reportes, registrar préstamos, devoluciones, libros y/o usuarios. 
**-Diseño:** Ahora necesitamos saber, cómo vamos a construir el sistema, se puede ir defidiendo por ejemplo, el diseño de la interfaz, base de datos, componentes y arquitectura. 
**-Desarrollo:** Manos a la obra, que en esta etapa los programadores empiezana crear el software en base a los requisitos y diseños ya establecidos. 
**-Pruebas:** Ya una vez desarrollado y finalizado en cuanto a código, funcionalides y diseño, se realizan pruebras, así se logran encontrar errores y se puedan solucionar, y pues se logra comprobar que el sistemaa cumple con los requisitos. 
**-Entrega:** Una vez probado, corregido y terminado, se entrega al cliente. 
**-Mantenimiento:** Después pueden aparecer algunos errores o necesidades de modificaciones, y si el cliente solicita se realizan actividades de mantenimiento.

## ¿En qué nos ayuda el desarrollo tradicional?
Nos ayuda principalmente a tener una estructura y planificación clara del proyecto en cual vamos o estamos trabajando, este puede ser útil en muchos casos, por ejemplo, tener requisitos bien definidos, los requisitos no van a cambiar mucho, se necesita una planificación detallada, el proyecto tiene procesos y estapas que deben seguirse de manera ordenada y/o se neceita bastante documentación del proyecto, por ejemplo, si una empresa sabe exactamente qué sistema necesita y los requisitos están establecidos desde el principio, un enfoque tradicional puede permitir organizar el proyecto alrededor de ese plan.

## ¿Cuál es el problema principal? 
Este desarrollo tradicional no logra funcionar bien, cuando los requisitos cambian mucho, por ejemplo en la misma biblioteca que hicimos nuestro desarrollo, planificamos y ya está todo listo y estamos en el paso de la creación, y nuestro cliente viene y nos dice: "Ahora, necesito agregar un sistema de reservas, también ocupo cambiar la forma de registrar los usuarios y modificar los resportes.", como el proyecto se planificó incialmente de una forma en específico, introducir nuevos cambios puede requerir modificar diseños, documentación, código y pruebas que quizá ya se habían hecho, es por ello que este desarrollo tiende a ser menos flexible antes cambios durante el proyecto. 

## ¿Qué es el desarrollo ágil?
En este tipo de desarrollo, se busca el enfoque en el desarrollo del software de una manera iterativa es decia que el trabajo se realiza mediante ciclos repetidos, incremental significa que el software va aumentando poco a poco sus funcionalidades y adaptable, porque en lugar de intentar construir todo un sistema de una sola vez siguiendo un plan ya establecido, pues se realiza dividiendo el trabajando en partes pequeñas, por ejemplo se desarrolla una parte y luego se prueba, se revisa, se recibe retroalimentación, se mejora y ya se sigue con la otra parte, en este desarrollo ágil se da mucha importancia a: 
* La colaboración.
* La comunicación.
* El software funcional.
* La retroalimentación.
* La adaptación a los cambios.
* La mejora continua.

## ¿Cómo funciona?
En este caso, en lugar de terminar todo y cuando ya esté absolutamente todo listo y mostrarlo, podríamos dividir las cosas por pequeñas partes, por ejemplo:
**-Primera iteración, registro de usuarios:** Una vez realizada, se prueba y una vez funcional se muestra al cliente, ahí el cliente podría decir que está bien pero necesita agregar otras cosas, lo que funciona ahí, es que se pueden realizar esos ajustes cuando aún no se ha terminado nada. 
**-Segunda iteración, registro y consulta de libros:** Se prueba y se presenta nuevamente, y el cliente nos da su retroalimentación.
**-Tercera iteración, sistema de préstamos:** Se prueba y se revisa
**-Cuarta iteración, devoluciones y reportez:** Se prueba y se revisa, se da retroalimentación y se realizan cambios. 
Y así sucesivamente, el sistema va creciendo progresivamente.

## ¿En qué nos ayuda el desarrollo ágil? 
La idea principal de este tipo de desarollo, es que el equipo logre adaptarse a las necesidades y cambios que el proyecto pueda presentar durante el proceso, y puede ser útil por ejemplo: 
1- Los requisitos pueden cambiar. 
2- El cliente necesita participar frecuentemente. 
3- Se necesita recibir reoalimentación durante el desarrollo. 
4- Se quieren realizar entregas frecuentes. 
5- Se necesita detectar problemas rápidamente. 
6- El proyecto requiere flexibilidad. 
Por ejemplo, si durante el desarrollo el cliente descubre que necesita una función nueva, el equipo puede analizarla y agregarla a una iteración posterior.

* Cabe aclarar que este desarrollo ágil, no significa programar rápido, ya que ágil no significa hacer las cosas sin planificación, porque si existe la planificación, perola planificación no necesariamente queda completamente fija desde el principio.

## Entonces, ¿cuál es la diferencia entre el desarrollo tradicional y el desarrollo ágil? 
La diferencia está en su forma de llevarse a cabo, mientras deslogábamos la información, íbamos entiendo que con el **desarrollo tradicional** primero debemos definir y planificar nuestro proyecto, para luego desarrollarlo por capas, y después presentarlo, mientras que en el **desarrollo ágil** dividimos el proyecto en pequeñas partes, desarrollamos, revisamos, recibimos retroalimentación y nos adaptamos a esos posibles cambios.
Es por ello que, cada forma de llevar a cabo el proceso de un proyecto, tiene sus necesidades y es por ello que hay que saber qué tipo de desarrollo tomaremos en cuenta para su planificación.
